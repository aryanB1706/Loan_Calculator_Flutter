# Deploy the backend on Render

About 10 minutes. You will end with a public HTTPS API that the mobile app (and
Postman) can use from anywhere, backed by MongoDB Atlas.

The repo already contains everything Render needs: [`render.yaml`](../render.yaml)
describes the service, and the backend reads `PORT` and `TRUST_PROXY` from the
environment.

## Before you start

- The code is pushed to GitHub.
- You have a MongoDB Atlas cluster (the free M0 is enough) and a Render account.

## 1. Prepare MongoDB Atlas

1. **Database user:** Atlas -> Database Access. If the password was ever shared or
   pasted anywhere, edit the user and set a **new** one.
2. **Network access:** Atlas -> Network Access -> Add IP Address -> **Allow access
   from anywhere** (`0.0.0.0/0`). Render's free instances have no fixed IP, so a
   single allowed address cannot work. The strong database password is what
   protects the data.
3. **Connection string:** Atlas -> Connect -> Drivers. Build the final value and
   include the database name `loan_calc` before the `?`:

   ```
   mongodb+srv://<user>:<password>@<cluster>.mongodb.net/loan_calc?retryWrites=true&w=majority
   ```

   URL-encode special characters in the password (`@` becomes `%40`, `:` becomes
   `%3A`, `/` becomes `%2F`).

## 2. Create the service on Render

**Easiest: Blueprint (reads `render.yaml`)**

1. Render dashboard -> **New +** -> **Blueprint**.
2. Connect your GitHub account and pick this repository.
3. Render shows the `credit-sea-api` service. It asks only for **`MONGO_URI`**:
   paste the string from step 1.
4. Click **Apply**. Render builds and starts the service.

Everything else is filled in for you: the JWT secrets and the admin key are
generated by Render, `TRUST_PROXY=1`, `OTP_MODE=demo`, health check
`/api/health`.

## 3. Check that it works

When the deploy shows **Live**, copy the service URL from the top of the page.
It looks like `https://credit-sea-api.onrender.com` (Render adds a suffix if the
name is taken, so use the one it shows).

```bash
BASE=https://credit-sea-api.onrender.com

curl $BASE/api/health
# {"success":true,"message":"Service is healthy","data":{"status":"ok",...}}

curl -X POST $BASE/api/loans/calculate \
  -H "Content-Type: application/json" \
  -d '{"amount":100000,"tenureMonths":12}'
# ... "emi":8884.88 ...

curl -X POST $BASE/api/auth/send-otp \
  -H "Content-Type: application/json" -d '{"phone":"9876543210"}'
# ... "provider":"demo","demoOtp":"123456"
```

If all three answer, the API and the database are connected. The first request
after a quiet period can take up to a minute (see "Free tier" below).

## 4. Point the app at it

The app ships pointing at `https://credit-sea-api.onrender.com`, set in
`mobile/lib/core/config/app_config.dart`. If your service got a different URL
(Render adds a suffix when a name is taken), change that one constant, or pass
the address when building. It is the server origin only, no `/api`:

```bash
cd mobile
flutter build apk --release
# or for another address:
flutter build apk --release --dart-define=API_BASE_URL=https://<your-service>.onrender.com
```

The APK is at `mobile/build/app/outputs/flutter-apk/app-release.apk`. Copy it to
a phone and install it (allow installs from your file manager if asked). For a
quick test without building:

```bash
flutter run
```

The Postman collection's `baseUrl` already points at the live service.

## 5. Using the admin endpoints

Render generated `ADMIN_API_KEY`. Open the service -> **Environment** -> reveal
the value, then use it exactly as locally:

```bash
curl -X PATCH $BASE/api/admin/loans/<loanId>/status \
  -H "x-admin-api-key: <the key>" -H "Content-Type: application/json" \
  -d '{"status":"under_review"}'
```

(`npm run simulate:loan` talks to the database directly, so run it on your own
machine with the same `MONGO_URI`.)

## Demo vs production

This setup is meant for demonstrating the project.

| Setting          | Demo (this guide)               | Real launch                                  |
| ---------------- | ------------------------------- | -------------------------------------------- |
| `NODE_ENV`       | `development`                   | `production`                                 |
| `OTP_MODE`       | `demo` (OTP is always `123456`) | `sms`, after implementing a provider         |
| Error responses  | can include stack traces        | never include stack traces                   |
| Admin access     | one shared API key              | real admin accounts                          |

The server enforces the right-hand column: with `NODE_ENV=production` it refuses
to start with `OTP_MODE=demo` or without `ADMIN_API_KEY`. Because the demo OTP is
public, do not put real user data on a demo deployment.

## Free tier: what to expect

- **Cold start.** A free service sleeps after about 15 minutes without traffic
  and takes 30 to 60 seconds to wake. The app waits up to 30 seconds to connect and
  60 to receive, which usually covers the wake-up; if not, it shows the "No
  internet connection" screen with **Try again**. Open `$BASE/api/health` in a browser
  just before a demo, or have a free uptime monitor ping it every 10 minutes.
- **Logs.** Render -> your service -> Logs shows requests and errors.
- **Redeploys.** `autoDeploy` is on, so every push to the main branch rebuilds.

## Troubleshooting

| Symptom                                           | Likely cause and fix                                                                                   |
| ------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| Deploy fails: "Invalid environment configuration"| A required variable is missing or too short. The log names it (for example `JWT_ACCESS_SECRET`).       |
| Log shows a MongoDB timeout or "bad auth"         | Atlas Network Access does not allow `0.0.0.0/0`, or the user or password in `MONGO_URI` is wrong.       |
| `/api/health` works but sign-in fails             | The database name is missing from `MONGO_URI`, or the string was pasted with `<password>` unreplaced.   |
| Users get "Too many requests" quickly             | `TRUST_PROXY` is not `1`, so everyone shares one rate-limit budget.                                     |
| Admin calls return `503`                          | `ADMIN_API_KEY` is not set on the service.                                                             |
| App cannot connect                                | `app_config.dart` or `API_BASE_URL` has a wrong address, `/api` at the end, or `http://` instead of `https://`. |
| First request is slow or fails, later ones work   | Cold start on the free plan (see above).                                                               |
